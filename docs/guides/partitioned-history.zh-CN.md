# Shared 活动状态与终态历史分离

[English](partitioned-history.md)

Redis和PostgreSQL将终态历史与普通操作恢复调度器的活动状态分开。
Driver、Shared和完整Transition保持兼容；TransitionPartial是可选存储辅助接口。

## 存储

开发阶段只维护一种布局，调度状态版本仍为1；不提供v1/v2协商、自动迁移、混合写入或降级路径。
使用新建的独占开发存储，旧开发数据不自动升级。不能为了切换布局直接删除仍有真实业务持有者
或幂等记录的资源；需要先结束相关工作，不能把重建开发数据当成在线升级。

Redis的state字段直接保存只含活动记录的JSON，同一HASH保留meta和r:*逐请求投影，
同槽stateKey:history有序集合索引终态回收时间。PostgreSQL直接创建带精确计数和回收时间列的
资源/请求表，普通操作只加载活动行与目标终态。EnsureSchema创建并检查该布局，不为本功能升级旧表；
原有部署DDL限制仍然适用。

## 语义与发布

部分状态包含全部排队/持有记录和目标完整终态，包括已经可以回收的目标；先检查请求冲突，再GC。
省略历史的数量必须精确，最早回收时间约束提交；回收时间仍为max(Finished+Retention,SubmitUntil)。
MaxRecords同时计算活动和保留终态。

到期、取消/释放、保存终态、复用容量与队列调度在同一资源串行化边界内提交。
PG使用同一事务。Redis原子检查更新锁owner与CommitWindow；多命令修改前清空state/meta，
最后一次写入同时发布两者。现有资源的空state表示发布未完成，不能当成新资源初始化。
这是失败完整性保护，不是存储版本标记。Redis运行时错误不会回滚已写命令；未完成资源保持不可用。
恢复前停止相关写入端并停止/排空其业务，再受控核查完整记录与索引；不能重置资源或盲目重放不确定操作。

本步仍可一次处理全部已到期历史，也仍恢复全部活动状态；续租不绕过公平和维护。
未访问终态只在写入及目标读取时校验，不再每次全量审计；应防止绕过驱动修改存储。
完整数据审计独立进行，后端持久性限制及应用租约/fencing义务保持不变。
