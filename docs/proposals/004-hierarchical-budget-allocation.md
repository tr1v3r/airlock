# 分层预算分配器方案

状态：独立实验提案，未实现，不改动现有公共 API。全部构件使用已发布的原语：
`Shared`（AcquireN/Renew/Release/Resize）、本地 `New(Config)` 及其 `Resize(0)`。
原型作为后续独立 PR 提交；合入顺序为本提案、分配器原型、微服务依赖保护示例。
本文数字是实验参数，不是生产推荐值。

## 目标和边界

千万级并发准入下，每请求走 Shared 不可用：1000 万等待者 × 50ms 轮询约 2 亿 QPS
读；排队记录约 10GB 状态，超过 MaxRecords 上限；即使 1% 写也远超单资源串行点
吞吐。全局精确公平必然存在全序化点，与该规模互斥。

本方案把仲裁频率降低约三个数量级：Shared 只做低频预算租约仲裁（每网关每周期
约十次操作），本地 Airlock 承接每请求内存仲裁。租户间公平精确到预算片粒度，
请求粒度有界近似；放弃每请求全局精确公平、全局 FIFO 排队与预算强回收（租约
不可撤销，靠 TTL 兜底）。排队必须是少数，超出排队配额的请求快速 429。

## 总体结构

三层各司其职：控制器（慢循环，10s–60s）按 SLA 权重 Resize 每个预算池；
每池一个 Shared 资源，网关竞争 chunk 租约；每网关每池一个本地 Airlock 实例，
capacity 等于当前持有量，执行请求粒度准入。

```
控制器 ──Resize 权重──▶ airlock:{池}（Shared/Redis）
                              │ chunk 租约
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
           网关 1           网关 2    …     网关 G
           Allocator + 本地 Airlock（每请求内存仲裁）
```

## 身份映射

- 预算池 = （容量池，SLA 档位）。容量池按被保护资源划分（推理模型、共享
  数据库、第三方配额）；档位为业务权重（免费/按量/企业/内部）。基数控制在
  池数 × 档位数，约十到百级；不按终端用户建池。
- Shared 层 `Request.Tenant` 填网关 ID：`MaxQueuedPerTenant` 天然成为每网关
  排队租约上限，即防垄断份额，不需要额外机制。
- 本地 Airlock 的 tenant 填 API key/调用方身份：预算片内做轮转公平。
- 终端用户配额在准入之前由配额/计费服务拦截，不进入本方案。

## 预算租约契约

Lease 整体释放、无部分释放，因此持有物为离散面额的 chunk 租约集合：

- 面额取 2 的幂（1/8/64，按池容量量级取），任意目标持有量用不超过约 10 张
  凑出，误差不超过最小面额。
- 加预算等于 `AcquireN(面额)` 新租约；减预算等于释放一张 chunk 租约；
  续约等于周期性 Renew 每张。某张续约失败只损失一个 chunk。
- 池内记录数 = 网关数 × chunk 数，约几十条；快照不随吞吐膨胀。
- 单请求权重超过网关全部持有量时直接 429，不入队。

## 控制循环

每网关每池，interval 基线 3s：

- 采样本地 `Stats()` 的 inUse 峰值（EWMA）与队列深度；需求 = max(峰值, inUse)
  + queued；目标 = clamp(需求 × headroom 1.3, 最小片, 池容量 × 最大份额)。
- 不足则按面额从大到小获取；获取不到保持现状，本周期内排队与 429 兜底。
- 过剩（利用率 < 0.5 连续两周期）按面额从大到小归还，防抖动。
- 目标为零时本地 `Resize(0)`：暂停准入，全部走排队或 429，等下周期。
- work-conserving：忙网关多拿；防垄断：单网关持有不超过池容量的约定份额。

## 请求路径

```
请求 → 本地 TryAcquireN(w)
  ├─ 成功 → 放行，完成后 Release
  ├─ ErrWouldBlock → 队列有空位且预计等待在上限内 → 本地排队（有界 FIFO，
  │   受保护队首语义仍生效）；否则 429 + Retry-After 对齐重平衡周期
  └─ ErrWeightExceedsCapacity → 直接 429
```

## 故障模式

- 网关崩溃：chunk 租约停止续约，TTL 到期自动归还池子；恢复界不超过 LeaseTTL。
- 闲网关囤积：捐赠循环每 interval 归还；进程假死由同一 TTL 兜底。
- Redis 不可达：已有 chunk 续约失败但本地 Airlock 照常服务直至租约过期，
  新预算获取不到，逐步降级为排队/429；降级平滑，宽限期等于 LeaseTTL。
- 控制器崩溃：池容量停在上次值，系统按旧权重继续运行。
- 租户封禁：控制器对该池 `Resize(0)`，新 chunk 不可得，存量租约自然排空。

## 参数基线（实验值）

| 参数 | 基线 | 依据 |
| --- | --- | --- |
| interval | 3s | 重平衡延迟与控制面负载折中 |
| LeaseTTL | 20s（约 7×interval） | 崩溃回收界，容忍两次续约失败 |
| headroom | 1.3 | 峰值突发吸收 |
| 面额 | 1/8/64 | 少于约 10 张凑任意目标 |
| 最大份额 | 50% | 网关数不少于 3 时防垄断 |
| 本地队列上限 | 1.0 × 持有量 | 排队少数原则 |

## 容量规划参考（假设 1000 万长连接、池容量 100 万）

- 入口网关约 120 台（基线 100 + 20% 冗余，多 AZ）：单台持有约 10 万并发流；
  到达率约 5K RPS/台；连接内存约 10GB/台。
- 预算面 Redis 一个小集群（3 主 3 从）：每池 key 约 1K QPS 以内，百池总量
  约 8 万 QPS 以内。
- 控制器 2–3 台；被拒流量由 LB/CDN 吸收，不到达网关。
- 准入基础设施与 GPU 容量解耦：池容量 C 来自被保护资源，C 之外全部快速拒绝。

## 与现有实现的差距

必需改动为零。可选优化不阻塞原型：`Lease.ReleaseN(k)` 部分释放（租约数从
约 10 降到 1，需要协议扩展与记录分裂语义）；同资源批量续约；池水位批量
Inspect 供控制器全局视图。网关数过千或池数过十万时按池分片多个 Redis。

## 验收方法

确定性测试使用内存驱动与模拟网关（固定种子），验证：

- 安全性：任意时刻全网关准入并发不超过池容量；租约归还后池内立即可再获取。
- work-conserving：需求集中的网关逐步获得更多份额；闲置份额在两个周期内归还。
- 有界不公平：两档位瞬时份额偏差不超过一个 chunk × 周期数。
- 崩溃恢复：模拟网关停止续约后，份额在 TTL 内回归并可被其他网关获取。
- 降级：后端不可达时本地准入持续到租约过期，新预算排队/429 按序降级。
- 封禁：`Resize(0)` 后新租约不可得，存量按 TTL 排空。

可选真实负载：固定到达轨迹与持有时间分布，多种子对比静态均分、本分配器与
单资源 Shared 的尾延迟、拒绝率与吞吐；不以毫秒级延迟作为 CI 门槛。
