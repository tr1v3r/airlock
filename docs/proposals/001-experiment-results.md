# RFC 001 实验结果

范围：内部原型，不是生产就绪声明。2026-10-22，Apple M3 Pro / darwin arm64，Go 1.24.13，x/sync v0.16.0。

## 结论

Gate 的真实 Acquire/Release 实现通过容量、轮转、取消/授予竞争、队列上限、Permit 并发重复释放和租户索引回收测试。全仓 test、race、vet 通过。

当前小规模负载支持 Gate 相比单 Weighted 改善稀疏租户的等待，但**不支持 Gate 优于合理的 tenant-first 两级组合**。尤其每租户上限等于总容量的 nested-4，在这些负载下同时保留吞吐和较低 B 延迟。保留 internal 原型继续评审，不升级成公开 API。

## 方法

- 总容量 4。原始 Pool、单 Weighted、租户优先获取的两级组合（每租户上限 1/2/4）、Gate，共六组。
- 每组 96 个请求，计划每 100µs 到达一个；洪峰场景每 12 个请求中的最后一个属于 B，其余属于 A；单租户场景全部为 A。
- 通常服务时间 1ms；混合场景按种子 1/2/3 生成约 25% 的 10ms 请求。其他场景的三个种子是重复运行，不产生不同服务轨迹。
- 通常队列上限 256；过载场景上限 12。全部比较对象外层都有同样的 `容量+队列上限` 在系统请求预算，满则快速拒绝；Gate 另有本身的排队上限。本次每租户排队上限等于全局上限，单独队列隔离由契约测试覆盖。
- 使用真实 goroutine 和 time.Sleep 模拟服务，不调用真实外部服务。全部拒绝/取消分别计数；等待分位数只包含成功请求，必须结合成功与拒绝数量阅读。
- 排队时间从 goroutine 开始执行计时，不含计划到达至 goroutine 启动的调度延迟。定时器会合并到达，不能视为精密负载发生器。

## 摘要

以下为三次运行的中位数。B 每次仅 8 个样本，不足以估计生产 p99；表格报告样本 p95，p99 原始字段仅供复现，不能据此宣布达到 RFC 的 p99 门槛。

| 场景 / 指标 | Weighted | nested-4 | Gate |
| --- | ---: | ---: | ---: |
| 单租户，总完成吞吐 /s | 3681.9 | 3664.7 | 3700.8 |
| 洪峰，B 样本 p95 | 13.087ms | 0.566ms | 0.723ms |
| 洪峰，总完成吞吐 /s | 3713.2 | 3664.7 | 3663.9 |
| 混合时长，B 样本 p95 | 52.316ms | 7.270ms | 7.160ms |
| 混合时长，总完成吞吐 /s | 1223.5 | 1180.2 | 1208.7 |
| 过载，B 完成 / 拒绝（每次） | 4 / 4 | 4 / 4 | 4 / 4 |

除过载场景外，全部请求完成，无拒绝和取消。过载时公平只发生在成功进入等待队列的请求之间，并未改善 B 入队机会。nested-1/2 在部分场景对 B 保护更强，但单租户吞吐受固定额度限制；见完整记录，不将其低吞吐外推到所有两级配置。

快速路径比较适配器的微基准中位数：Weighted 约 21.51ns/op、16B/1 allocation；Gate 约 37.27ns/op、40B/2 allocations；nested-4 约 36.57ns/op、24B/1 allocation。这些值包含返回释放闭包/方法值的适配开销，不是底层 Weighted 的裸 API 开销。Gate 没有证明快速路径性能优势。

## 尚未证明

真实接入效果、生产 p99、持续负载稳定性、全进程内存上界和租户公平对实际资源时间的影响。负载输出中的内存是整个测试进程采样，包含 goroutine、测试框架等分配；它不证明长期无泄漏。租户索引为空也不等于 map 内部分配立即归还给操作系统。

本轮没有对 Failsafe-go 做实测，也没有声称有市场空白。若继续验证，应增加样本、持续多租户竞争和跨轮到达轨迹，并以 nested-4 为强基线；不能仅靠单 FIFO 的改善决定发布。
