# Airlock 混合负载服务水平与容量边界探索

2026-10-30，本机隔离 Redis/PostgreSQL 上对 `819e030` 做了 36 次独立试验（6 场景 × 2 后端 × 3 次，每次 15 秒），未修改运行时。**高历史量与高并发下，500ms 操作预算已明显不足；应优先控制单资源历史规模和等待压力，再做热路径拆分。** 这些是当前实现的工作负载诊断，不是最大服务容量、生产 SLO，也没有旧实现对照，不能据此证明某次 PR 的性能回归。

版本边界：本轮固定 `819e030` 的 Driver 路径。实验期间 dev 已前进到 `f739f5e`（#58，Shared polling jitter）；该变更不改 Driver，但本数据没有覆盖其 Shared 端到端行为。后文轮询优化建议不表示最新 Shared 缺少 jitter，后续应在包含 #58 的版本上联合验证 Shared、自适应轮询与失败清理。

## 负载与口径

Driver 级闭环：Submit → 排队时每 50ms Observe → 获准后模拟持有 600ms、每 200ms Renew → Release。固定 weight=1、8 个租户、TTL=2s、每次操作独立超时 500ms；连接池上限 `max(workers,16)`，GOMAXPROCS=12。没有真实业务，也未测 Shared 端到端路径或加权公平性。600ms 持有自身约束准入速率在 capacity/0.6s 附近，慢响应还会降低闭环发起速率。

H 是人工预置终态数，C 是容量，W 是 worker 数。初始 seed 使用后端时钟，经 Transition 校验与正常 Driver 写路径预热；不计初始化耗时。普通场景 retention=60s，三轮均确认 seed 未被 GC；运行产生的新终态也保留，所以 H=0 不表示全程没有历史。MaxRecords=100000，队列上限 `max(2W,3C)`。每次使用独立资源，交错 case/后端顺序；没有丢弃失败试次或调整参数重跑。

吞吐分母固定 15s，分子是窗口内完成的 measured 业务操作；包括返回错误的尝试，不包括 cleanup 或跨结束边界调用。准入/s 仅计窗口内成功交付且预算可用的业务 grant，不含 seed。`boundary` 和 `cleanup` 原样留存。延迟 CSV 同时给出每种操作的 all/ok/error 分层；ok 只表示调用无错误，Observe queued 也是 ok，不能等同业务完成。

## 错误、取消与续租预算

全部 180363 个 measured 调用中 3472 个返回 deadline；另外记录 105 个 boundary 错误和 2337 个 cleanup 错误。没有把这些结束或清理错误混入 measured 分母。错误原文与分类可在 raw 中复查：deadline 是客户端超时，**不证明后端未执行或未提交**。本工具不重放失败的原 mutation；用同一 request 的 Cancel 尝试清理，之后 worker 可能创建新的 synthetic lifecycle。失败清理可能占用容量直到 TTL，这种反馈和清理额外负载是模型的一部分。

成功 cleanup Cancel 返回 cancelled 共 1644 次；cleanup Cancel 错误 2269 次。measured/边界业务响应没有返回 expired，不能据此认定后端没有发生过期（失联/超时后的状态不能从错误推断）。集中到期场景另用 seed 读回证明 64 条预置活跃/排队记录过期。

预算是保守客户端估算，不是精确后端 TTL：新预算=返回 Remaining−完整 RTT；旧预算完成值=调用开始时旧 deadline 余量−RTT。成功 Renew 的旧预算完成值最低 473.9ms；已确认 grant 未出现预算不可用，`UnusableGrants=0`。这不抵消大量未确认的超时，且只覆盖已观察响应。逐轮、成功/失败分层见 [renewal-budget.csv](renewal-budget.csv)。

## 集中到期与 GC

Case5 预置 1000 终态 +32 grant +32 queued，全部边界在 seed 后2s。测量开始到边界实际为 1936.2–1961.2ms（预热耗时已扣除）；三轮两后端最终 seedHistory=0、seedExpired=64。所有试次末态 grant 数不超过容量且 seed 校验通过；这些是末态检查，不是全程无超发证明。

[expiry-windows.csv](expiry-windows.csv) 按调用开始相对到期边界分成 500ms 桶，保留每个操作/结果的 N 与分位数，用于区分事件前、中、后；跨边界完成的调用属于开始桶。这不是与 Case4 的匹配对照（W 不同，而且 GC 后 H 降为0），不能将 whole-trial 差异归因于 GC 成本。事件期间的峰值只能描述局部波动。 三轮合计的开始时间 cohort 如下（各操作混合，展示样本量/最大延迟，不作为全局分位数或因果估计）：

| 后端 | 相对边界窗口 ms | N | 返回错误 N | 最大延迟 ms |
|---|---|---|---|---|
| Redis | -1000–0 | 1793 | 0 | 29.0 |
| Redis | 0–500 | 198 | 0 | 401.6 |
| Redis | 500–1500 | 565 | 0 | 487.4 |
| PostgreSQL | -1000–0 | 1819 | 0 | 25.3 |
| PostgreSQL | 0–500 | 199 | 0 | 317.4 |
| PostgreSQL | 500–1500 | 531 | 0 | 184.7 |

边界前主要是排队 Observe；边界后获准工作引入 Renew/Release，操作构成变化也会影响局部最大值，不能把全部变化算作维护执行时间。Redis 此场景的 deadline 出现在其他窗口，不能从这三个 cohort 的零错误推导全试次正常。

## 后续优化顺序

1. **先建立单资源保留历史预算。** H10000 已超过本实验 500ms 延迟预算；实际阈值需按业务 workload 重测，不能把本机 H1000 当通用安全上限。部署控制 Retention/去重窗口与单资源请求速率，必要时按独立容量域拆分资源；不可为了变快缩短业务要求的幂等保护。MaxRecords 仅是硬保护，不能代表延迟预算。
2. **设计上分离活动调度与终态幂等历史。** 当前两后端仍有全状态解码/校验/扫描成本；Redis 增量投影、PG 批量 delta 写未消除该量级。优化应保留 CommitWindow、重试/未知结果语义和公平安全，并补真实后端同负载对照及 profile。
3. **降低等待与失败反馈流量。** 在不损害公平/取消/租约预算的前提下评估有上限的自适应 Observe 间隔、抖动和单资源 in-flight 控制，监测 cleanup 失败。单纯加大 timeout 可能拖长持有并挤压续租旧预算，应最后根据业务 deadline 验证。
4. **扩展验证边界。** 追加 Shared 端到端、单位权重以外的混合权重、多个独立资源、长时自然历史增长与真实网络/故障恢复；然后才评估开放环到达率和服务容量。此次没有生产 durability 配置对照、跨机延迟或 failover。

## 数据与复现

- [summary.json](summary.json)：36 次完整汇总；[raw/](raw/)：每次 gzip JSONL 操作样本及独立 summary，失败也保留。
- [environment.json](environment.json)：主机、Docker/镜像 digest、Go版本、源代码 hash；Apple M3 Pro 12逻辑CPU/36GiB，OrbStack，Redis8.10.2、PG18.6，Go1.27.3。
- [工具说明](../../../tools/mixedload/README.md)：生命周期与字段口径；[run.sh](../../../tools/mixedload/run.sh) 为矩阵定义。

```sh
# 在隔离、无竞争测量窗口；地址只能指向一次性服务
cd tools/mixedload
GOWORK=off go build -o /tmp/airlock-mixedload .
REDIS_ADDR=127.0.0.1:PORT POSTGRES_DSN='postgres://USER:PASS@127.0.0.1:PORT/DB?sslmode=disable' ./run.sh
python3 analyze.py ../../docs/validation/mixed-capacity
```

每次试验资源自动清理，原始结果不会依赖存活容器；重跑请用 OUTPUT_DIR 指向新的目录避免混入旧结果。镜像使用 environment.json 的 digest 可固定版本。分位数采用排序后 floor(q×N)，p95至少20样本、p99至少100样本，接近阈值时仅是接近最大值的不稳定估计；不合并三轮掩盖波动。三轮短窗口仍不足估计长期尾部与可靠性。

验证：新工具模块 gofmt、go test -race ./...、go vet ./...、go mod verify；Python/runner 语法检查通过。根模块 go test ./... 与 go vet ./... 通过。该工具是独立模块，现有 CI 不会自动覆盖，需显式手动运行或后续加入工具 checks。运行时未改动。独立 agent 复算36份 raw 的 phase、分位数、seed 与预算检查通过。
