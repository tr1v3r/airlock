# Shared 的默认配置与使用层次

状态：本 PR 实现；不创建 tag/release。

## 1. 在构造入口补默认值，不修改 driver 协议

`NewShared` 只要求资源名和有效的准入配置；在校验和复制之前，为零值补齐：
LeaseTTL=30s、MaxWait=30s、SubmitWindow=5s、Retention=1m、MaxRecords=10000、
OperationTimeout=5s、PollInterval=50ms。负值、超出协议上限和不合法精度仍拒绝。
不改变 SharedOptions 的字段结构，不新增与 Config.Admission 重叠的配置入口。

容量、优先级和队列上限没有隐式修改。特别是零队列仍表示不排队，MaxWait 默认值不代表启用等待。
直接调用 Driver/Transition 的作者仍需提供完整不可变 ResourceConfig；客户端只传已补齐的配置，
各 driver 不分别解释默认值。已有显式合法配置保持原行为，NewDistributed 兼容入口使用相同规则。

## 2. 默认值是公开策略，有成本且不能静默迁移

30s 租约为显式续租留出余量，同时限制无人续租的遗留授权期限；不是允许任务忽略失效运行 30s。
30s 等待是默认上限，ctx 可收紧。5s 提交窗口配合 5s 操作上限限制迟到请求。
1m 终态保留为恢复提供窗口；历史记录只能在提交窗口也结束后回收。
10000 条是协议允许的最大记录上限，按需使用而非预分配，避免默认上限小于某些显式容量设置。
但它不是“足够所有负载”的承诺：高请求率仍可能 ErrHistoryFull，整资源快照成本随记录数增长。
50ms 轮询降低空查频率但增加结果可见延迟；实际负载应测量后调整。

同一资源的所有客户端必须使用相同的已解析 ResourceConfig。默认值属于公开兼容契约，
未来变更须明确迁移；不根据客户端本地环境、版本时间或 driver 类型自动推导。
已有资源不会应用新默认值覆盖存储策略。采用默认值与原策略不同时，保留原显式配置，
或在旧任务结束后按部署方案切换新资源。本文没有增加在线改配置。

## 3. 易用性不通过隐藏任务执行或自动续租实现

本地 Airlock/Permit 和 Shared/Lease 保持各自生命周期。不会用无 ctx、无 error 的 Release
掩盖远端失败，也不把 Lease 伪装成永不过期的 Permit。
生命周期辅助代码只放在可运行 example，库不执行 worker、不跟踪批次完成。
应用自行选择续租频率、任务取消方式和有限清理重试。

示例独立监听失效，续租出错即取消任务。业务须响应 ctx 并等待自己的子任务全部退出。
业务结束后停止并 join 续租/监听 goroutine，再以独立短 ctx 释放。同一 Lease 清理最多重试一次，
不重跑业务；两次失败保留“结果未知”的错误。此顺序避免主动释放时业务仍运行，
但不能阻止不响应取消、进程长暂停或外部系统的陈旧写入。

## 4. 文档按使用者分层

README 先选择本地或共享入口，Shared 入门只介绍申请与租约生命周期；协议的五个方法、
Request/LeaseRef/Transition、原子提交和恢复放入自定义 driver 指南。
memory 首先定位为契约测试和演示参考实现；普通单进程控制推荐 New(Config)。
它不持久化、不同实例不共享，也不能作为 Redis/PG 故障时的降级。

## 验证

默认配置与显式等价配置在同一后端互通；零队列仍立即拒绝；显式值不覆盖、非法值不吞掉，
与已有不同策略冲突时不改写后端。生命周期测试覆盖续租成功、续租失败、续租阻塞时的失效、
父 ctx 取消、已失效租约不启动任务、业务错误和同凭证释放重试。三个 driver 独立模块
固定到真实已推送的新 core，并使用 GOWORK=off 检查；不借助 replace 验证旧依赖。
